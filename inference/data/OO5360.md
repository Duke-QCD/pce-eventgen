# O-O input adapter

The public pipeline supports `--system OO5360`, but does not distribute an O-O study's measurement tables, digitization evidence, source figures, assumed proxy inputs or fit results. Supply your own reviewed data through `--data-dir`. The installation walkthrough uses the bundled AuAu200 reference tables and a generated model grid.

## Directory and table contract

Point `--data-dir` at a `centrality/` directory with this layout:

```text
your-data/
  centrality/
    dN_deta_charged_CMS.dat
    mean_pT_charged_ATLAS.dat
    v2_2_charged_ALICE.dat
    v3_2_charged_ALICE.dat
  derived/
    dN_dy_K0S_vs_mult.dat
    dN_dy_Xi_tot_vs_mult.dat
    dN_dy_Omega_tot_vs_mult.dat
    mean_pT_K0S_vs_mult.dat
    mean_pT_Xi_tot_vs_mult.dat
    mean_pT_Omega_tot_vs_mult.dat
```

These names identify the adapter's expected observables; they do not certify a supplied file's source or acceptance. Centrality tables have `cent_low cent_high cent_mid val err`, with bounds in percent. Identified tables have `dNch_deta val err`, ordered by strictly increasing positive multiplicity. Values and errors must be finite, with positive errors. Mean pT is in GeV; yields and charged multiplicity are dimensionless. Measured flow tables contain v_n{2}; the fitter converts them to signed-cumulant space once.

K0S is a single species. Xi/Omega yields and mean pT refer to the combined particle/antiparticle sample. The adapter's default excludes K0S mean pT; `--drop-specs` replaces the exclusions and `--drop-specs ''` retains all enabled groups. Unselected groups do not require their measurement files. Retained multiplicity points depend on coverage by every usable design, not on a fixed table-row count.

The adapter includes a 5% diagonal discrepancy term, flags assumed/mixed uncertainties for the configured identified yields, and cuts the third-harmonic comparison at 45% centrality. These are explicit adapter choices. Review them against your data, acceptance and model resolution before drawing physics conclusions; changing file locations alone does not change the observable specification.

## Matrix and preflight

The matrix needs a matching same-stem metadata file, `system="OO5360"` and `analysis_profile="oo_cross_full_pt027_flat/v3"`. This profile defines the charged mean-pT adjustment and cross-oversample flow estimator. Fitted flow bins require the per-design `charged_flow_sample_usage` metadata; the default permitted same-sample fallback pair-weight share is zero. See the [matrix contract](../../docs/reference/analysis-inputs.md) for the full definitions.

```bash
python check_inputs.py --system OO5360 \
  --matrix /absolute/path/to/model_matrix.npz \
  --design /absolute/path/to/original/design.dat \
  --data-dir /absolute/path/to/your-data/centrality
```

Run this from `inference/` with its environment active. Inspect skipped measurements, usable designs and warnings. Preflight establishes software compatibility, not experimental validity or convergence. Continue with the [general production workflow](../PRODUCTION.md).

## Optional correlated proxy extension

`--oo-yield-proxies` explicitly enables assumed charge-summed pi/K/p yield proxies. It is off by default. This extension requires a compatible supplied bundle under sibling `optional/`, `derived/`, `uncertainties/` and `sources/` directories: three proxy tables, joint covariance and metadata, the K0S anchor and the source evidence used by the proxy builder. No such study bundle is included in the public repository.

The proxy tables are `optional/proxy_dN_dy_{pion,kaon,proton}_vs_mult.dat`, with the same three-column convention. `optional/yield_proxy_covariance.npz` carries labelled values and the joint covariance; `optional/yield_proxy_metadata.json` records the assumptions. The pipeline checks the builder's reproducibility contract and uses the selected covariance submatrix, preserving correlations with the anchor and other proxies. Marginal DAT errors must not be treated as independent constraints. `build_oo_yield_proxies.py --help` describes the preparation interface; the source declares its required evidence files. This is an assumption-based sensitivity extension, not a substitute for measured identified yields and experimental covariance.

## Local storage and reproducibility

`inference/data/OO5360/` is an ignored legacy staging location, retained for users with existing saved input paths. New analyses may use an external directory or ignored `config/users/<study>/` instead. The supplied data directory and its relative sibling layout must remain intact for replay.

Saved fits record input hashes and paths. Preserve the exact tables, covariance, source evidence, model matrix, original design, source version and library versions. Moving or revising inputs is a separate analysis change; never edit saved hashes to force cache reuse. Dataset-specific audit scripts and analyses belong with the local study. Public tests exercise the adapter and likelihood using synthetic fixtures.
